# 9주차 · 전반부 복습 + Pandas의 한계 — 언제 손절하나

## 오늘 얻어가는 것

Pandas가 버거워지는 지점을 직접 만들어보고, Polars·Dask로 넘어갈지 판단하는 기준을 세운다.

## 준비된 데이터

없음 — 대용량 데이터를 저장소에 커밋하지 않는다. 대신 `generate_big_data.py`를 실행해 각자 로컬에 만든다.

```bash
python generate_big_data.py 5000000 big_transactions.csv   # 500만행, 약 300~400MB
```

컴퓨터 사양에 따라 행 수를 줄여도 된다(`1000000`부터 시작 추천).

## 해야 할 일

1. **전반부(1~8주) 복습** — 지금까지 쓴 진단→AI 처리→검증 루프를 한 문장씩 정리한다.
2. **Pandas로 큰 파일을 읽어본다** — `pd.read_csv()`로 읽으면서 메모리 사용량(`memory_usage(deep=True)`)과 걸리는 시간을 잰다.
3. **버거워지는 지점을 찾는다** — 행 수를 100만 → 300만 → 500만으로 늘려가며 읽기 시간이 어떻게 변하는지 기록한다. 컴퓨터가 멈추거나 메모리 오류가 나는 지점을 찾아본다(너무 위험하면 직전 단계에서 멈춘다).
4. **Polars로 같은 작업을 해본다(데모)** — `pip install polars` 후 같은 파일을 읽고 집계하는 시간을 비교한다.
5. **판단 기준을 세운다** — "행 수가 얼마를 넘으면", "메모리가 얼마를 넘으면" Pandas 대신 Polars·Dask·DuckDB를 고려할지 자기 기준을 한 문장으로 적는다.

## 산출물

- 행 수별 읽기 시간·메모리 사용량 표
- Pandas vs Polars 비교(선택)
- "나는 이 기준을 넘으면 도구를 바꾼다" 한 줄 판단 기준
