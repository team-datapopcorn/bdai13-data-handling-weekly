# 8주차 · 재현 가능한 코드 — 폴더·컨벤션·Git + 과제 1 안내

## 오늘 얻어가는 것

새 데이터를 다루지 않는다. 대신 1~7주차에 만든 코드와 결과물을 **다른 사람(또는 미래의 나)이 다시 실행할 수 있는 형태**로 정리한다.

## 준비된 데이터

없음. 지금까지 각자 만든 노트북·CSV·쿼리가 재료다.

## 해야 할 일

1. **폴더 구조를 정한다** — 예: `data/`(원본·결과 CSV) · `notebooks/`(주차별 노트북) · `README.md`(실행 순서).
2. **README를 쓴다** — "이 폴더를 처음 보는 사람이 어떤 순서로 실행해야 1주차부터 7주차 결과가 재현되는가"를 적는다. 실행 순서, 필요한 라이브러리, 데이터 출처(이 저장소의 어느 폴더인지)를 명시한다.
3. **Git으로 버전 관리를 시작한다** — `git init`, 의미 있는 단위로 커밋 나누기, `.gitignore`로 대용량/캐시 파일 제외.
4. **재현 테스트** — 폴더를 통째로 다른 곳에 복사(또는 동료에게 요청)해서 README만 보고 처음부터 다시 실행되는지 확인한다. 안 되면 README가 아니라 코드나 경로가 문제다.
5. **과제 1 안내를 확인한다** — 이번 주 발표되는 과제 1은 "데이터 정리 + 검증"이다. 평가 포인트는 결과가 아니라 **재현성과 검증 과정**이라는 걸 다시 확인한다.

## 산출물

- 정리된 프로젝트 폴더 구조
- 실행 순서가 적힌 README
- 처음 커밋부터 지금까지의 Git 로그

## 검증 체크

- [ ] README만 보고 처음 실행하는 사람도 순서를 알 수 있는가
- [ ] 절대 경로(`/Users/내이름/...`)가 코드에 남아있지 않은가
- [ ] `.gitignore`로 불필요한 파일(캐시, 대용량 원본)을 뺐는가
